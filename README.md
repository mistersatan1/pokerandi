# 랜덤 포켓 디펜스 (v2)

> Claude Code 로 작업한다면 **`CLAUDE.md`** 부터 — 명령 · 구조 · 작업 규칙 · 열린 문제가 정리돼 있다.

브라우저에서 `index.html` 을 열면 바로 돌아간다. 설치도 서버도 필요 없다.
개인 팬 프로젝트이며 상업적 배포는 하지 않는다.

> **운으로 뽑지만, 조합식과 위치로 운을 뒤집는 랜덤 디펜스.**

ES 모듈 대신 클래식 `<script>` 를 쓰는 이유가 이것이다 — 모듈은 `file://` 에서 CORS 로 막혀
반드시 서버를 띄워야 한다. 서버로 보고 싶다면 `python3 -m http.server 8000`.

## 한 판의 흐름

```
라운드 시작 (대기 없음)
   ↓  적이 걸어오고 포켓몬이 자동으로 싸운다
소환 — 골드로 랜덤 포켓몬을 뽑는다
   ↓  뽑은 개체는 가장 잘 싸우는 빈 칸에 자동으로 앉는다
조합식 확인 — "이 재료가 하나 모자라네"
   ↓  필요한 재료가 나올 때까지 뽑는다 (안 나오면 조각으로 산다)
조합 — 정해진 재료를 모아 한 등급 위를 만든다
   ↓  같은 타입이 모이면 시너지도 함께 오른다
마지막 적 처치 → 다음 라운드
   ↓  9 / 17 / 25 / 33 라운드마다 새 등급 해금
70라운드 최종 보스 (61라운드에 불멸·초월 없이는 넘기 힘든 벽)
```

패널은 짙은 네이비, 필드는 밝은 풀밭이다. 금색은 "지금 할 수 있는 것"에만 쓴다 —
완성 가능한 조합식, 고른 칸, 골드. 빨강은 라이프에만 쓴다.

1920×1080 / 1366×768 / 1280×720 에서 스크롤 없이 한 화면에 들어간다.
1100px 미만이면 세로로 풀리고 영역마다 자체 스크롤이 생긴다.
마우스와 터치가 같은 경로를 쓴다 — 끌어서 칸을 바꾸는 것이 태블릿에서도 된다.

## 설계에서 지킨 것

**대기 시간을 만들지 않는다.** 소환·배치·조합·강화는 전투가 돌아가는 중에 한다.
적을 다 잡으면 바로 다음 라운드가 오고, 못 잡고 있으면 다음 라운드가 겹쳐 들어온다.

**등급은 테두리 색으로 읽는다.** 필드·보유·조합식·상점·도감이 같은 색 규칙을 쓴다.

**칸마다 성격이 다르다.** 같은 사거리라도 덮는 경로 길이가 칸마다 크게 갈린다.
칸을 클릭하면 `근접용 / 중거리용 / 장거리 전용 / 구석 자리` 로 알려 준다.

**스킬은 허공에 쓰지 않는다.** 사거리 안에 적이 있을 때만 터지고,
침묵 중에는 쿨다운도 멈춘다. 배율은 실효 공격력 기준이라 강화·시너지·버프가 스킬에도 실린다.

**라이프는 후반 몇 라운드분이다.** 한 라운드를 흘려도 만회할 기회가 있고, 계속은 없다.
이게 없으면 "충분하거나 즉사" 뿐이라 중간 결과가 사라진다.

## 테스터에게 보내기

```bash
node tools/build-tester.js
# → dist/포켓몬랜덤디펜스_테스트.html  (약 2.3MB, 이 파일 하나만 보내면 된다)
```

HTML·CSS·JS·그림이 전부 한 파일에 들어간다. 받은 사람은 더블클릭만 하면 된다.
작업 기록(`VERSION.md`·`CHECKPOINT.md`·`docs/`)과 검사 도구(`tools/`)는 들어가지 않는다.
제목에 빌드 시각이 붙어 있어 테스터가 어느 판을 했는지 말할 수 있다.

`index.html` 만 따로 보내면 안 된다 — 스크립트 46개·CSS 3개·그림 104장을 옆 폴더에서 읽기 때문에
빈 화면만 뜬다.

## 실행과 점검

```bash
# 게임
index.html 을 브라우저로 연다

# 도구
node tools/redesigncheck.js    # 게임 규칙·밸런스 회귀 검증
node tools/bootsmoke.js        # 실제 부팅 순서 + 화면 패널이 채워지는지
node tools/uicheck.js          # UI 구성 · 공격 연출 · 고유 스킬
node tools/rendersmoke.js      # 렌더 코드 실행
node tools/integritycheck.js   # 스크립트 연결·로드 순서
node tools/autoplay.js 24      # 자동 플레이 통계 (모드명을 두 번째 인자로)
node tools/balance.js 50       # 라운드별 필요 DPS
node tools/assets.js           # 이미지 현황
tools/sprites.html             # 생성 스프라이트 미리보기
tools/cleansprites.py          # PNG 에 구워진 액자 잔상 제거 (선택)
node tools/build-tester.js     # 테스터용 단일 HTML 만들기 → dist/
```

`tools/selftest.js` 는 v1 전제라 쓰지 않는다.

## 현재 밸런스

아래 표는 50라운드 시절 수치라 **오래됐다**. 최신 측정은 `VERSION.md` 맨 위 절들을 본다
(70라운드 확장 · 61라운드 벽 · 역할 보정 · 버퍼 이후).

표본은 모드마다 30~40판이다. **20판 이하 표본은 클리어율이 ±15%p 흔들린다** —
수치를 만질 때는 40판 이상으로 잴 것.
핵심 수치: `hpGrowth 1.109` · 흔함 확률 최소 50% · 라이프 60(후반 2라운드분) · 조합 보정 1.4.
모든 모드를 30판 × 2 로 쟀다(일반 쉬움·어려움·지옥은 30판).
스킬 추가와 해금 앞당김으로 플레이어 전력이 두 번 올라 체력 곡선을 그만큼 다시 잡았다
(근거는 `VERSION.md`).

## 그래픽과 연출

필드의 포켓몬은 `assets/pokemon/*.png` 를 쓴다. 파일이 없으면 `SpriteFactory` 가
개체 데이터로 코드로 그린다 — 이미지가 하나도 없어도 게임은 정상 동작한다.

**공격 연출은 55종이 전부 다르다.** 스프라이트를 새로 만들지 않고,
`data/attackfx.js` 의 개체별 설정을 `AttackFxRenderer` 하나가 읽어 그린다.

| | |
|---|---|
| 공격 방식 | 투사체 · 빔 · 브레스 · 참격 · 폭발 · 번개 · 광역 · 궤도 |
| 명중 연출 | 불꽃·물방울·전기·잎·얼음조각·독구름·링·그림자·먼지·금속·별·깃털·충격·포자·꽃잎·동전 |
| 등급 | 올라갈수록 크고 복잡해진다. 전설만 치명타에서 아주 짧게 화면이 흔들린다 |
| 스킬 | 평타와 확실히 다른 대형 연출 + 시전자 발밑 링 + 스킬 이름 표시 |
| 성능 | 파티클 고정 풀 1,600개. 풀이 차면 스스로 줄인다. 실전 부하에서 60fps |

파이리는 불꽃 탄, 피카츄는 번개, 이상해씨는 씨앗, 나옹은 동전, 리자몽은 화염방사,
니드킹은 뿔 찌르기다. 같은 연출을 쓰는 개체가 없다는 것을 `uicheck` 가 감시한다.

적은 10라운드마다 다른 몬스터 계열로 보인다(코로몬 → 뿔몬 → 아구몬 → 아그몬 → 테일몬,
보스 그레이몬 → 가루몬 → 메탈그레이몬 → 피에몬 → 오메가몬). 그림 49장은
`assets/enemies/digimon/`, 구간별 대응은 `js/data/enemyskins.js` 에 있다.
겉모습만 바뀌고 적의 성질과 수치는 그대로다.

`assets/` 에 PNG 를 넣으면 생성 스프라이트보다 우선한다. 목록은 `assets/MANIFEST.md`.

## 소리

배경음 3곡(평시·전투·보스)과 효과음 19종이 **전부 WebAudio 합성**이다. 음원 파일이 없다.
상단 스피커 버튼에서 배경음·효과음 음량과 음소거를 조절하고, 설정은 저장된다.
브라우저 정책상 첫 클릭에서 소리가 깨어난다.

## 알려진 문제

- 드래곤·에스퍼·고스트 타입 포켓몬이 로스터에 없다. 그 타입 시너지는 목록에서 빼 두었다
  (`js/data/types.js` 에 되살릴 자리가 주석으로 남아 있다)
- 전기 2종 · 격투 1종뿐이라 그 시너지는 같은 종을 여러 마리 올려야 켜진다
- 밸런스 수치는 전부 **무전략 봇 기준**이다. 사람이 하면 더 쉽다
