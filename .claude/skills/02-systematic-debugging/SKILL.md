# Systematic Debugging

## 원칙
증상과 원인을 분리한다. 첫 번째로 떠오른 원인을 사실처럼 취급하지 않는다.

## 절차
1. 오류 메시지와 증상을 정확히 확인한다.
2. 문제가 발생하는 조건을 재현한다.
3. 관련 코드와 데이터 흐름을 추적한다.
4. 가능한 원인을 2~3개로 좁힌다.
5. 로그, 값, 호출 순서 등 증거를 확인한다.
6. 가장 작은 범위의 수정안을 적용한다.
7. 같은 오류가 사라졌는지 재현 테스트한다.
8. 관련 기능에 회귀가 없는지 확인한다.

## 특히 확인할 것
- undefined/null
- 배열 인덱스
- 상태 초기화
- 이벤트 중복 등록
- 저장/불러오기 데이터 버전
- 비동기 처리 순서
- DOM과 게임 상태의 불일치
- 라운드/보스 상태 전환
- 조합식 데이터와 실제 로직의 불일치
