# Game Motion Design — 포랜디

## 목적
정적인 웹페이지를 즉각 반응하는 게임으로 만든다. 애니메이션은 장식보다 상태 변화와 보상을 전달하는 피드백이다.

## 모션 단계
Micro feedback: 약 100~250ms — 클릭, 재화 증가, 선택, 작은 상태 변화.
Gameplay feedback: 약 250~700ms — 공격, 피격, 소환, 조합.
Event animation: 특별 이벤트 — T4/T5, 보스, 10라운드, 대형 보상.

정확한 시간은 기존 게임의 템포에 맞춰 조정한다.

## 소환
생성 위치 피드백 → 포켓몬 등장 → 등급 강조 → 정상 상태 복귀.
긴 연출은 피한다.

## 조합
재료 강조 → 결과 위치로 연결되는 느낌 → 짧은 강조 → 결과 등장 → 등급에 맞는 보상 피드백.

## T4/T5
T4는 짧은 특별 등장 효과, T5는 더 강한 등장 경험을 준다. 전체 화면을 장시간 가리지 않는다.

## 보스
보스 등장 시 일반 전투와 다른 진입감을 준다.
- 짧은 경고
- 보스 이름
- 위협 상태
- 보스 체력
가능하면 전투 필드를 계속 볼 수 있게 한다.

## 시너지
활성화 순간 아이콘 강조, 숫자 변화, 짧은 pulse 또는 연결 효과를 사용한다. 지속적으로 움직이는 효과는 피한다.

## 전투
피해 숫자가 과도하게 겹치지 않게 한다. 치명타/특수 피해는 일반 피해와 구별한다.

## 브라우저 성능
가능하면 transform, opacity, CSS animation/transition을 사용한다. 불필요한 매 프레임 layout 계산을 피한다. 기존 Canvas 렌더링 루프가 있다면 충돌하지 않게 한다.

## 접근성
prefers-reduced-motion을 고려한다. 모션이 꺼져도 상태 변화와 보상이 텍스트/아이콘/색상 등으로 이해되어야 한다.

## 구현 전 확인
요소 생성/삭제 위치, 상태 변경 시점, 중복 이벤트, 기존 애니메이션 충돌, 작은 화면에서의 가림 여부를 확인한다. 모션 추가 때문에 게임 로직을 불필요하게 재작성하지 않는다.

## 최종 기준
플레이어가 애니메이션을 '보고 있다'기보다 게임이 '즉각 반응한다'고 느끼게 만든다.
