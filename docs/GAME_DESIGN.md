# 랜덤 포켓 디펜스 — 게임 기획 & 기술 설계서

> 버전 0.1 (PHASE 1 확정본) · 개인 팬 프로젝트
> 이 문서의 모든 수치는 `js/data/` 폴더에 그대로 옮겨져 코드가 아니라 데이터로 관리된다.

## 1. 최종 게임 기획

> **구조 수정 1차 반영됨.** 아래 수치 중 일부는 자체 평가 후 바뀌었다.
> 노멀 30 → 20웨이브, 소환 30 → 45골드, 이자 정률 4% → 10골드당 1,
> 등급 합성 3마리 고정 → 등급별 3/3/5/7, 필드 16칸 등거리 → 커버리지 편차 ×5.
> 바뀐 이유는 README 의 "구조 수정 1차" 표에 있다.

**한 줄 정의**
운으로 뽑고, 위치로 배치하고, 합성으로 키워서 몰려오는 적을 막는 4×4 슬롯 자동전투 디펜스.

**차별점 3가지**

1. **위치가 곧 전략이다.** 적이 지나가는 길(레인)이 3개 있고, 배치 슬롯 16칸은 레인 사이에 끼어 있다. 앞줄은 위쪽 레인만, 뒷줄은 아래쪽 레인만 닿는다. 사거리가 긴 포켓몬만 두 레인을 동시에 때린다. → "강한 걸 아무 데나" 가 통하지 않는다.
2. **운을 뒤집는 장치가 있다.** 천장, 연속 꽝 보정, 웨이브별 확률 상승, 그리고 무엇보다 **합성**. 커먼도 3단 진화 + 각성까지 가면 레어 1성보다 강하다.
3. **골드를 안 쓰는 것도 선택지다.** 웨이브 클리어 시 보유 골드의 4%를 이자로 준다(최대 40). "지금 뽑을까, 굴릴까"가 매 웨이브 실제 고민이 된다.

**승패 조건**
- 적이 출구를 통과 → 라이프 −1 (보스는 −5)
- 라이프 0 → 게임 오버
- NORMAL 모드에서 20웨이브 클리어 → 승리

## 2. 핵심 게임 루프

```
웨이브 시작 (준비 15초 / 스킵 가능)
   ↓
골드로 랜덤 소환 → 빈 슬롯에 자동 안착
   ↓
드래그로 재배치 (레인 거리 = 사거리 판단)
   ↓
적 등장 → 자동 전투 (평타 + 스킬 + 타입 효과)
   ↓
처치 골드 + 웨이브 보너스 + 이자
   ↓
같은 포켓몬 3마리 → 합성 (진화 / 각성)
   ↓
시너지 재계산 → 다음 웨이브
   ↓
10웨이브마다 보스
```

플레이어가 매 웨이브 마주하는 4가지 질문:
- 지금 골드를 뽑기에 쓸까, 이자로 굴릴까
- 이 슬롯은 위 레인용인가 아래 레인용인가
- 이 커먼 3마리를 합성할까, 시너지 카운트를 위해 남길까
- 보스가 곧 오는데 격투/단일딜러 비중이 충분한가

## 3. 포켓몬 등급

| 등급 | 색상 | 기본 스탯 배율 | 최대 진화 단계 | 각성 가능 |
|---|---|---|---|---|
| COMMON | 회녹 `#8a9a8f` | 1.0 | 3단 | O |
| RARE | 청 `#4f8fd6` | 1.45 | 3단 | O |
| EPIC | 보라 `#a366e0` | 2.1 | 2~3단 | O |
| LEGENDARY | 호박 `#f0a02e` | 3.2 | 1단(각성만) | O |
| MYTHIC | 자홍 `#ff5fa2` | 4.5 | 1단(각성만) | O |

**핵심 밸런스 규칙**: 커먼 3단 + 각성 ≈ 에픽 1단. 즉 운이 나빠도 시간과 합성으로 따라잡을 수 있다.

## 4. 소환 확률

기본 확률 (`js/data/rarity.js`)

| 등급 | 확률 |
|---|---|
| COMMON | 58% |
| RARE | 27% |
| EPIC | 11% |
| LEGENDARY | 3.4% |
| MYTHIC | 0.6% |

보정 시스템

- **소프트 천장**: 에픽 이상 없이 8회 연속 시, 매 회마다 에픽+ 확률 +4%p 누적
- **하드 천장**: 12회 연속 에픽 미만 → 다음 소환 에픽 이상 확정
- **전설 천장**: 60회 누적 전설 미만 → 다음 소환 전설 이상 확정
- **웨이브 보정**: 웨이브 10부터 에픽/전설 확률에 `1 + (wave−10) × 0.012` 배율 (최대 1.5배)
- **특별 소환권**: 보스 처치 보상. 레어 이상 확정 티켓
- **지라치 패시브**: 필드에 있으면 전 등급 상향 보정 (MYTHIC 고유 효과)

## 5. 포켓몬 역할

숫자만 다른 포켓몬은 만들지 않는다. 모든 개체는 아래 역할 중 하나 이상을 갖는다.

| 역할 | 하는 일 | 약점 |
|---|---|---|
| SINGLE_DPS | 단일 대상 고화력 | 다수 적에 무력 |
| AOE_DPS | 범위 피해 | 보스 단일에 약함 |
| DOT | 화상/독 지속 피해 | 즉발 화력 낮음 |
| SLOW | 이동속도 감소 | 공격력 매우 낮음 |
| CONTROL | 빙결 / 기절 | 확률 의존, 쿨 김 |
| BUFFER | 아군 공격력·공속 상승 | 직접 화력 거의 없음 |
| DEBUFFER | 적 방어력 감소 | 단독으로는 무의미 |
| BOSS_KILLER | 보스·정예에 추가 피해 | 잡몹 처리 최악 |
| ECONOMY | 처치 시 추가 골드 | 전투력 하위 |
| UTILITY | 복제·쿨감·확률 상승 등 | 상황 의존 |

예시 배치 (전체 로스터는 `js/data/pokemon.js`에서 관리)

- COMMON: 캐터피 계열(DEBUFFER), 구구 계열(SINGLE_DPS·고공속), 뿔충이 계열(DOT), 꼬렛 계열(ECONOMY), 모래두지 계열(AOE_DPS), 디그다 계열(다중타겟), 주뱃 계열(DOT·고속)
- RARE: 파이리 계열(AOE·화상), 꼬부기 계열(SLOW), 이상해씨 계열(ECONOMY·풀), 피카츄 계열(연쇄), 가디 계열(SINGLE_DPS), 식스테일 계열(DEBUFFER), 고라파덕 계열(BUFFER), 이브이(**분기 진화** — 샤미드/쥬피썬더/부스터 중 선택)
- EPIC: 리올→루카리오(BOSS_KILLER), 잉어킹→갸라도스(저스펙 고성장 도박형), 아공이 계열(치명타), 고오스 계열(방어 무시), 메타몽(UTILITY·인접 최강 복사)
- LEGENDARY: 프리져(빙결 광역), 썬더(연쇄), 파이어(화상 광역), 루기아(전체 버프), 칠색조(라이프 회복), 레쿠쟈(초고화력 단일), 뮤츠(궁극기 폭발), 그란돈/가이오가(필드 전체 효과)
- MYTHIC: 뮤(모든 스킬 복사), 세레비(전체 쿨감), 지라치(소환 확률 상승), 아르세우스(전 타입 시너지 1카운트 부여)

## 6. 합성 시스템

**기본**: 같은 종·같은 단계 3마리 → 다음 단계 1마리

```
파이리 ×3 → 리자드     리자드 ×3 → 리자몽     리자몽 ×3 → 리자몽 ★각성
```

합성 시 반드시 **최소 2가지 이상**이 바뀐다. 공격력만 오르는 합성은 금지.

| 단계 | 바뀌는 것 |
|---|---|
| 1→2단 | 스탯 + 사거리 또는 공속 |
| 2→3단 | 스탯 + 공격 방식 변경(단일→관통/광역 등) + 신규 스킬 |
| 3단→★각성 | 스탯 + 패시브 추가 + 스킬 강화판 + 외형 이펙트(오라) |

**분기 진화**: 이브이는 합성 시 3택 모달이 뜬다. 팀 시너지에 따라 선택이 갈린다.

**전설/신화**: 진화 단계가 없는 대신 3마리 모으면 곧바로 ★각성. 중복이 사장되지 않는다.

### 등급 합성 (PHASE 9 에서 추가)

```
같은 등급 3마리 (서로 다른 종이어도) → 상위 등급 랜덤 1마리
```

같은 개체 3마리 규칙만으로는 게임이 성립하지 않는다는 것이 실측으로 드러났다.
소환 가능한 종이 33개라 한 판(약 100회 소환) 동안 같은 종 3마리가 잘 모이지 않고,
짝만 남은 개체들이 전부 죽은 자원이 된다. 오토플레이가 11~13웨이브에서 멈췄다.

등급 합성을 넣은 뒤 같은 오토플레이가 20웨이브를 클리어한다.

재료 조건을 좁게 잡아 안전장치를 둔다.
- **1단계·비각성 개체만** 재료가 된다 → 공들여 키운 개체가 실수로 갈려 나가지 않는다
- 같은 종 합성이 항상 우선한다 → 종 합성에 쓰일 칸은 등급 합성 후보에서 빠진다
- 결과는 랜덤 1단계다 → 종을 고를 수 없다는 것 자체가 비용이다

**강화(개별 업그레이드)**: 골드로 특정 개체 공격력 +8% (중첩 최대 5회, 비용 지수 증가). 합성 재료로 쓰면 강화가 사라지므로 "이 애를 키울까, 재료로 쓸까" 선택이 생긴다.

**승계 규칙** (PHASE 9 확정)
- 진화·등급 합성: 강화는 사라진다. 다른 개체가 되기 때문이다
- 각성: 같은 개체가 강해지는 것이므로 강화가 남는다
- 투자 골드는 셋 다 승계된다. 합성이 "돈을 버리는 행위"가 되면 아무도 하지 않는다
- 결과물은 재료 중 강화가 가장 많던 칸에 앉는다. 플레이어가 신경 써서 잡아 둔 자리를 존중한다

## 7. 타입 시스템

포켓몬 원작 상성표는 복사하지 않는다. 디펜스에 필요한 **8개의 기계적 효과**로 단순화한다.

| 타입 | 고유 효과 |
|---|---|
| 불꽃 | 화상 — 3초간 공격력 30% 지속 피해 |
| 물 | 슬로우 — 이동속도 25% 감소 |
| 전기 | 연쇄 — 인접 1~3체에 50% 피해 전이 |
| 얼음 | 빙결 — 15% 확률로 1.2초 정지 |
| 격투 | 보스·정예에 +40% 피해 |
| 고스트 | 적 방어력 무시 |
| 드래곤 | 치명타 피해 +60% |
| 땅 | 착탄 지점 광역 피해 |
| 독 | 중첩 독 (최대 5스택) |
| 강철 | 적 방어력 감소 디버프 |
| 에스퍼 | 아군 스킬 쿨다운 감소 |
| 풀 | 처치 시 추가 골드 |
| 비행 | 공격속도 증가 |
| 벌레 | 소환 비용 할인 |
| 바위 | 기절 확률 |
| 악 | 체력 25% 이하 적 처형 |
| 페어리 | 라이프 보호막 |
| 노말 | 고유 효과 없음 — 대신 스탯이 높음 |

**시너지(같은 타입 보유 수)**

| 타입 | 2개 | 4개 | 6개 |
|---|---|---|---|
| 불꽃 | 화상 피해 +30% | +70% | 화상이 광역 확산 |
| 물 | 슬로우 +10%p | +20%p | 슬로우가 중첩 |
| 전기 | 연쇄 +1 | +2 | 연쇄 피해 100% |
| 비행 | 공속 +12% | +25% | +40% |
| 격투 | 보스 피해 +15% | +35% | — |
| 풀 | 골드 +10% | +25% | — |
| 드래곤 | 치명타율 +8% | +18% | — |
| 고스트 | 방어 무시 30% | 100% | — |

시너지는 **필드가 바뀔 때마다** 재계산되고 사이드 패널에 항상 표시된다.
완성된 시너지는 밝게, 미완성은 "몇 마리 더 필요한지"가 나온다.

### 구현하면서 확정된 것 (PHASE 10)

**타입 효과는 바닥선이다.** 개체 데이터에 `slowMul` 같은 값이 있으면 그쪽을 쓰고,
없으면 타입의 기본값을 쓴다. 즉 "물 타입이면 최소한 감속은 한다"가 보장되고,
개체가 더 잘할 수도 있다. 데이터를 적을 때 모든 필드를 채우지 않아도 된다.

**보너스는 한 곳에서만 만든다.** `SynergyManager.bonus` 객체 하나에 모든 수치가 모이고
전투·경제·UI 가 전부 그것만 읽는다. 각자 세면 표시와 실제가 어긋난다.

**지속 피해에 두 가지 규칙이 있다.**
- 화상: 갱신형. 때릴 때마다 새로 걸지 않고 더 센 쪽으로 갱신한다
- 독: 중첩형. 한도까지 쌓이고, 넘치면 가장 약한 스택을 밀어낸다

**달성 불가능한 시너지는 만들지 않는다.** 처음 표를 짤 때 바위·악·페어리는 로스터에
해당 타입 포켓몬이 0종이라 영영 켜지지 않는 죽은 규칙이었다. 테스트가 이를 잡아
포켓몬 7라인(꼬마돌·코일·삐·쥬쥬·알통몬·니로우·델빌 계열)을 추가하고,
그래도 종이 적은 타입(얼음·바위·고스트·페어리)은 최고 단계를 4 → 3 으로 낮췄다.
`selftest.js` 가 이 조건을 계속 검사한다.

## 8. 적 종류

| 종류 | 특징 | 대응법 |
|---|---|---|
| 일반형 | 기준치 | — |
| 고속형 | 이동속도 2.2배, 체력 낮음 | 슬로우·빙결 |
| 탱커형 | 체력 4배, 느림 | 지속 피해(DOT) |
| 장갑형 | 방어력 높음 (고정 피해 감소) | 고스트·강철 |
| 무리형 | 한 번에 8~12마리 | 광역 |
| 재생형 | 초당 체력 3% 회복 | 순간 화력 |
| 분열형 | 죽으면 2마리로 쪼개짐 | 광역 |
| 보호막형 | 흡수 실드 보유 | 연쇄·다중타격 |
| 보스 | 체력 12~20배 + 고유 패턴 + 제한시간 | 격투·단일 딜러 |

방어력 공식: `실피해 = 피해 × (100 / (100 + 방어력))` — 방어력이 아무리 높아도 피해가 0이 되지 않는다.

## 9. 웨이브 구조

| 웨이브 | 구성 |
|---|---|
| 1–4 | 일반형만. 튜토리얼 구간 |
| 5–9 | 고속형 합류 |
| 10 | **보스 1** |
| 11–19 | 탱커형·장갑형 합류, 무리형 등장 |
| 20 | **보스 2** |
| 21–29 | 재생형·분열형·보호막형 |
| 20 | **보스 2 (NORMAL 최종)** |
| 31+ | ENDLESS 전용. 웨이브 5마다 보스 |

체력 스케일링: `hp = base × 1.155^(wave−1) × 모드배율`

**구간 블렌딩**: 구간이 바뀌는 순간 적 구성이 통째로 갈리면 난이도가 절벽처럼 뛴다.
블렌딩 없이 측정했을 때 웨이브 11의 웨이브당 증가율이 ×1.56 (평소 ×1.21) 으로 벽이 생겼다.
그래서 새 구간의 앞 5웨이브는 이전 구간 풀과 선형으로 섞는다 (`WaveData.blendWaves`).

**실측 결과** (`node tools/balance.js`)

| 항목 | 값 |
|---|---|
| 웨이브당 난이도 증가율 (중앙값) | ×1.22 |
| 20웨이브 누적 획득 골드 | 약 15,500 |
| 한 판 소요 시간 (1배속) | 18~23분 (3배속 6~8분) |
| 슬롯당 필요 DPS | 웨이브 10 → 20 · 웨이브 20 → 350 · 웨이브 30 → 2,500 |

마지막 줄이 PHASE 6~7 에서 포켓몬 스탯을 설계할 때의 목표치다.
커먼 3단 각성 하나가 이 값을 혼자 내면 안 된다. 시너지와 버퍼가 나머지를 메우게 한다.
보상 스케일링: `killGold = 2 + floor(wave/3)`, `waveClear = 20 + wave × 3`

## 10. 보스 구조

보스는 4가지 패턴 슬롯을 가진다: 등장 연출 / 주기 패턴 / 페이즈 전환 / 처치 보상.

| 보스 | 주기 패턴 | 페이즈 전환(체력 50%) |
|---|---|---|
| 폭주대장 (10) | 15초마다 잡졸 3마리 증원 | 가속 — 이동속도 ×1.45 |
| 방해자 (20) | 11초마다 강한 슬롯 2칸 침묵(3.5초) + 18초마다 철갑 2마리 | 경화 — 방어력 ×2 |
| 파괴자 (30) | 10초마다 충격파(반경 240) + 13초마다 침묵 3칸 + 15초마다 보막 3마리 | 폭주 — 패턴 주기 ×0.65, 속도·방어 상승 |

**패턴은 전부 데이터다.** `enemies.js` 의 `patterns` 배열에 `{ id, first, every, ... }`
를 적으면 끝이고, `BossManager` 는 "패턴 종류를 실행하는 법"만 안다.
새 보스를 만들 때 시스템 코드를 고칠 일이 없다.

**침묵은 무작위로 고르지 않는다.** DPS 가 높은 슬롯부터 노린다.
무작위로 고르면 "아무 일도 안 일어난 것 같은" 판이 절반쯤 생긴다.

**패턴 셋은 각각 다른 배치 습관을 벌준다.**
증원은 단일 딜러만 모은 보드를, 침묵은 한 마리에 버프를 몰아준 배치를,
충격파는 앞줄에 전부 몰아둔 배치를 벌준다.

**패턴을 미리 알려 준다.** 보스 웨이브의 준비 시간 동안 사이드바에 어떤 패턴이
몇 초마다 오는지 표시되고, 전투 중에는 보스 체력바에 다음 패턴이 예고된다.
처음 만나서 당하고 배우는 것보다, 알고도 막지 못해서 지는 쪽이 낫다.

**제한시간**: 보스 등장 후 60초 내 미처치 시 보스가 즉시 출구로 돌진한다 → 시간 압박이 "보스 킬러 유무"를 실제 변수로 만든다.
**처치 보상**: 골드 + 특별 소환권 1장 + 라이프 +1

### 보스 체력을 정하는 방식 (PHASE 5 에서 확정)

보스 체력을 고정 숫자나 고정 배수로 적으면 모드가 바뀌는 순간 무너진다.
엔드리스는 5웨이브마다 보스라 같은 배수가 초반엔 벽이 되고 후반엔 반대로 물러진다.

그래서 절대값 대신 **직전 웨이브를 잡는 데 든 일의 몇 배인가**로 정의한다.

```
보스 체력 = (그 웨이브가 잡몹으로만 구성됐다면 나왔을 총 체력) × 배수 × 보스 개성값
배수 = 2.2 + (몇 번째 보스인가 − 2) × 0.2      (최대 8단계까지 상승)
```

이러면 `bossEvery` 가 1이든 5든 10이든, 어느 웨이브에 나오든 체감이 유지된다.
개별 보스의 `hp` 값은 참고용으로만 남기고 실제 계산에 쓰지 않는다.

구간(band)이 바뀔 때 기준선이 계단처럼 뛰는 문제는 경계 직후 3웨이브에 걸쳐
선형 보간해서 없앴다. 실제 등장 구성은 그대로고, 보스 체력을 재는 자만 매끈해진다.

`tools/balance.js` 가 4개 모드 전부에 대해 이 곡선을 검사하며,
`tools/selftest.js` 의 "난이도 곡선" 섹션이 회귀를 막는다.

## 11. 재화 시스템

**골드 획득**
- 적 처치: `5 + floor(wave/2)` (풀 시너지·이코노미 역할로 증가)
- 웨이브 클리어: `45 + wave × 8`
- 이자: 보유 10골드당 1 (최대 35) — 웨이브 클리어 시
- 보스 처치: 150 + wave × 5
- 포켓몬 방출: 투자 골드의 50% 환급

**골드 사용**
- 랜덤 소환: 기본 45, 누적 10회마다 +9 (최대 130)
- 개별 강화: 24 × 1.6^등급 × 1.5^강화횟수 (공격력 +12%/회, 최대 5회)
  - 처음엔 +8% · 비용 배수 1.9 로 잡았는데, 같은 골드를 소환에 쓰는 게 언제나 이득이라
    아무도 누를 이유가 없는 함정 버튼이었다. 오토플레이가 이를 잡아내 수치를 고쳤다.
  - 지금은 전설 1마리 만렙(+60%)이 소환 19회분이다. 둘 다 할 만한 선택이 됐다.
- 슬롯 확장: 220 / 480 (기본 16칸 → 최대 18칸)
  - 확장 칸은 띠의 정중앙이라 위아래 레인에서 똑같이 105px 거리다.
    사거리 하나로 두 레인을 덮으므로, 값을 치를 이유가 위치 자체에 있다.
- 리롤 티켓 구매: 80

**설계 의도**: 소환 비용이 서서히 오르므로 후반에는 "무지성 소환"이 불가능해지고, 이자와 합성이 상대적으로 강해진다.

## 15. 예상되는 기술적 문제와 해결책

| # | 문제 | 해결책 | 적용 |
|---|---|---|---|
| 1 | ES 모듈은 `file://`에서 CORS로 차단됨 → 더블클릭 실행 불가 | 모듈 대신 **클래식 script + 전역 `RPD` 네임스페이스**. 파일 하나당 IIFE로 감싸 전역 오염 방지 | PHASE 2 |

| 5 | 탭 전환 후 복귀 시 dt 폭증 → 적 순간이동 | `dt`를 100ms로 클램프 | PHASE 2 |
| 6 | HiDPI 화면에서 캔버스가 흐릿함 | `devicePixelRatio` 스케일 + 논리 좌표계 1000×600 고정 | PHASE 2 |
| 7 | 적 60마리 × 포켓몬 18마리 타겟 탐색 = 매 프레임 1080회 | 타겟 캐시(0.1초 유지) + 사거리 사각형 사전 필터 + 죽은 적 즉시 제외 | PHASE 7 |
| 8 | 데미지 숫자·이펙트 객체가 초당 수백 개 생성 → GC 스파이크 | 오브젝트 풀링 | PHASE 7 |
| 9 | 저장 포맷이 바뀌면 기존 플레이어 데이터 파손 | `save.version` 필드 + `migrate()` 체인. 파싱 실패 시 try/catch로 초기화 | PHASE 13 |
| 10 | 밸런스 수정 때마다 로직 파일을 뒤져야 함 | 로직에 매직넘버 금지. 모든 수치는 `data/` 또는 `RPD.Config` | 전 구간 |
| 11 | 시스템끼리 직접 호출하면 순환 의존 발생 | `EventBus` 경유. 예: 적 사망 → `enemy:died` 이벤트 → 경제·통계·이펙트가 각자 구독 | PHASE 2 |
| 12 | `localStorage`가 사파리 프라이빗 모드 등에서 예외 | 쓰기/읽기 전부 try/catch, 실패 시 메모리 저장으로 폴백 | PHASE 13 |

**hpMul 만 다르면 "노멀인데 아픈 것"에 불과하다.** 그래서 위 보정들을 뒀고,

**보스 러시에 bossShareMul 이 필요한 이유:** 잡몹 웨이브의 체력은 여러 마리에 나뉘어
있지만 보스는 한 덩어리다. 같은 배수를 쓰면 광역 딜러가 통째로 놀아서 2웨이브부터
벽이 된다. 실측으로 0.62 를 찾았다.

**보스 러시에 goldMul 2.4 가 필요한 이유:** 처치할 잡몹이 없어 처치 보상이 거의
안 들어온다. 보정 없이는 4웨이브에서 소환할 골드가 떨어져 굶어 죽는다.

**남은 문제:** 보스 러시는 초반 편차가 크다(4판 실측 1·2·7·10웨이브).
