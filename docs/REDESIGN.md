# 리디자인 기술 설계서

> 대상: 포켓몬 랜덤 디펜스 (현재 PHASE 15 완료 상태)
> 목표: 「랜덤 소환 → 조합식 발견 → 재료 수집 → 진화 → 상위 전력 → 더 높은 라운드」 구조로 재정립
> 이 문서는 **코드 수정 전 합의용**이다. 승인 후 STEP 1부터 착수한다.

## A. 현재 시스템 분석

### A-1. 실제 구현 현황 (코드 기준)

| 영역 | 구현 내용 | 파일 |
|---|---|---|
| 포켓몬 | 56종 (소환 가능 25종) · 계열(family) + 단계(stages) 구조 | `data/pokemon.js` |
| 등급 | 5단계 COMMON/RARE/EPIC/LEGENDARY/MYTHIC · 고정 확률 | `data/rarity.js` |
| 소환 | 고정 확률 + 천장 3종 + 라운드 보정 + 티켓 | `systems/SummonManager.js` |
| 합성 | 같은 종 3마리 → 진화 / 분기 / 각성 / 등급 합성 | `systems/FusionManager.js` |
| 시너지 | 10종 · 필드 바뀔 때 재계산 | `systems/SynergyManager.js`, `data/types.js` |
| 전투 | 타겟팅 5종 · 공격방식 4종 · 타입 효과 11종 · 오라 | `systems/CombatManager.js` |
| 라운드 | PREPARE(8초) → SPAWNING → CLEARING → 보상 | `systems/WaveManager.js` |
| 경제 | 소환 / 강화 / 슬롯확장 / 방출 / 이자 | `systems/EconomyManager.js` |
| 보스 | 증원·침묵·충격파 + 2페이즈 + 폭주 | `systems/BossManager.js` |
| 저장 | 도감(등록 수) · 모드별 기록 · 설정 · 마이그레이션 | `systems/SaveManager.js` |
| 필드 | 16칸 + 확장 2칸 · 커버리지 편차 ×5.06 | `data/map.js`, `systems/FieldManager.js` |

### A-2. 새 기획과 이미 맞는 부분

- **랜덤 소환 + 천장** — 그대로 쓸 수 있다
- **위치 시스템** — 커버리지 편차 ×5.06. 새 기획이 건드리지 않는 영역이고, 이 게임의 가장 강한 자산이다
- **보스 패턴** — 기획서가 "유지"를 명시했다
- **타입 효과 11종** — 스킬 시스템의 토대로 재사용 가능
- **측정 도구** — 리디자인 후 밸런스를 다시 잡으려면 필수

### A-3. 새 기획과 충돌하는 부분

| # | 충돌 | 현재 | 기획 |
|---|---|---|---|
| 1 | 성장 경로 | 같은 종 3마리 자유 합성 | **지정 조합식** |
| 2 | 중복 처리 | 등급 합성 (같은 등급 N → 상위) | 제거 또는 조각 |
| 3 | 등급 이름·서열 | COMMON~MYTHIC | 흔함/안흔함/특별함/희귀함/전설 |
| 4 | 소환 확률 | 전 구간 고정 + 보정 | **라운드별 해금** |
| 5 | 라운드 사이 | 준비 8초 (전체 시간의 16%) | 대기 제거, 연속 진행 |
| 6 | 도감 | 등록 수만 표시 | **영구 버프** |
| 7 | 스킬 | 별도 시스템 없음 (타입 효과가 대신) | 희귀함부터 고유 스킬 |
| 8 | UI 배치 | 시너지·합성이 사이드바 패널 | 시너지 오른쪽 고정 · **조합식 필드 아래 고정** |
| 9 | 최종 라운드 | 20 | 50 (예시) |

## B. 제거 / 축소할 시스템

### B-1. 완전 제거

| 시스템 | 이유 | 대체 |
|---|---|---|
| **등급 합성 (TIERUP)** | 기획서가 명시적으로 제거 대상으로 지정. 실측에서도 전체 합성의 71%를 먹어 주력 루트를 잠식했다 | **조각(Shard) 시스템** — 중복 방출 시 조각 획득, 조각으로 특정 재료 교환 |
| **각성 (AWAKEN)** | 조합식 체계에서는 "최종 단계 3마리"라는 개념 자체가 사라진다 | 조합식의 최상위 레시피로 흡수 |
| **분기 진화 (BRANCH)** | 이브이 전용 특수 케이스. 조합식이면 「이브이 + 물의돌 → 샤미드」로 자연스럽게 표현된다 | 재료가 다른 3개의 레시피 |
| **라운드 준비 시간** | 기획 10번 | 상시 조작 |
| **빠른 시작 버튼** | 준비 시간이 없으면 의미 없음 | — |

### B-2. 축소

| 시스템 | 현재 | 변경 |
|---|---|---|
| 같은 종 합성 | 주력 루트 | **보조** — 같은 종 3마리는 "조각 3개"로 환산 |
| 슬롯 확장 | 2칸 구매 | 실측 구매율 0.04회/판으로 사실상 죽어 있다. **라운드 보상으로 전환** 검토 |
| 강화 | 골드 소모 +12%×5 | 유지하되 조합식과 경쟁하지 않게 비용 재조정 |

### B-3. 제거하지 **않을** 것 (기획서와 다른 판단)

> **등급 합성을 "아무 대체 없이" 제거하면 안 된다.**
> 기획 30번은 "운이 너무 나쁘면 아무것도 못 한다"를 금지한다. 등급 합성은 현재 유일한
> 구제 장치다. 이걸 없애면서 조각 시스템을 같이 넣지 않으면, 조합식 재료가 안 나오는 판이
> 그대로 사망 확정이 된다. **조각 시스템은 선택이 아니라 필수 대체재다.**

## C. 유지할 시스템과 이유

| 시스템 | 유지 이유 |
|---|---|
| **필드 커버리지** | 칸마다 경로 커버리지가 128~648px로 다르다. 기획서가 건드리지 않는 영역이고, "어디에 둘까"가 이 게임의 유일한 실시간 판단이다 |
| **전투 엔진** | 타겟팅·공격방식·상태이상은 스킬 시스템의 실행 기반이 된다. 새 스킬은 전부 이 위에 얹는다 |
| **보스 패턴** | 기획 24번이 유지를 명시 |
| **타입 시너지** | 기획 15~18번이 강화를 요구. 위치만 오른쪽으로 옮긴다 |
| **저장 + 마이그레이션** | 도감 버프가 붙으면 저장 포맷이 바뀐다. 버전 체계가 이미 있어 v2→v3 전환으로 끝난다 |
| **모드 시스템** | modifiers 구조라 라운드 수·확률 곡선만 바꾸면 새 기획에 그대로 맞는다 |
| **측정 도구 5종** | 리디자인 후 밸런스를 처음부터 다시 잡아야 한다. 이게 없으면 감으로 돌아간다 |
| **SpriteFactory** | 개체 수가 늘어도 이미지 작업이 필요 없다 |

## D. 새 게임 구조

### D-1. 핵심 루프

```
라운드 시작 (대기 없음)
      ↓
적 등장 · 자동 전투 (계속 진행 중)
      ↓
골드 획득 → 소환 (전투 중 언제든)
      ↓
조합식 확인 — "리자드가 필요하네"
      ↓
필요한 재료가 나올 때까지 소환
      ↓
조합 완성 → 진화 → 상위 등급 확보
      ↓
타입 시너지 동시 상승
      ↓
마지막 적 처치 → 0.8초 연출 → 다음 라운드
      ↓
[10/20/30/40] 새 등급 해금 연출
      ↓
보스 → 더 높은 라운드
```

### D-2. 현재와 달라지는 체감

| | 현재 | 리디자인 후 |
|---|---|---|
| 소환 동기 | "더 센 게 나왔으면" | **"리자드가 나왔으면"** (목표가 구체적) |
| 합성 판단 | 3마리 모이면 무조건 합성 | 재료를 아껴 둘지, 다른 조합에 쓸지 |
| 라운드 진행 | 8초 정지 → 전투 | 끊김 없음 |
| 등급 기대 | 항상 같은 확률 | **10라운드마다 새 등급 해금** |
| 판을 넘는 성장 | 기록 숫자만 | 도감 버프 |

## E. 조합 시스템

### E-1. 데이터 구조 변경

**현재**: 계열(family) + 단계(stages) — 진화 결과물은 소환으로 얻을 수 없다.

```js
{ family: 'charmander', rarity: 'RARE',
  stages: [ {id:'charmander'}, {id:'charmeleon'}, {id:'charizard'} ] }
```

**변경**: 모든 개체가 **독립 엔트리**가 되고, 진화는 **레시피 테이블**로 분리한다.

```js
// data/pokemon.js — 개체는 평평한 목록
{ id: 'charmander', name: '파이리', rarity: 'COMMON',  types: ['FIRE'],
  attack: 20, attackSpeed: 0.9, range: R.MID, attackType: 'SINGLE',
  targeting: 'FIRST', skill: null, desc: '...' }

{ id: 'charmeleon', name: '리자드', rarity: 'UNCOMMON', types: ['FIRE'],
  attack: 52, attackSpeed: 0.95, attackType: 'SPLASH', splash: 38, skill: null }

{ id: 'charizard',  name: '리자몽', rarity: 'SPECIAL',  types: ['FIRE','FLYING'],
  attack: 150, range: R.LONG, attackType: 'SPLASH', splash: 58,
  skill: 'blast_burn' }
```

```js
// data/recipes.js — 조합식은 별도 파일
{
  id: 'charizard',                    // 결과물
  materials: ['charmander', 'charmeleon'],
  hint: '불꽃 화력의 중심',
  unlockRound: 11                     // 이 라운드부터 목록에 노출
}
```

### E-2. 조합식 설계 원칙

1. **재료는 전부 소환으로 얻을 수 있어야 한다** — 재료가 또 조합 결과물이면 진입 장벽이 이중이 된다. 3단계 이상 체인은 최상위 1~2개만 허용
2. **재료 수는 2~3개** — 4개 이상은 완성 체감이 너무 멀다
3. **같은 종 2개 요구 금지** — 그건 자유 합성의 재탕이다
4. **결과물은 재료보다 정확히 한 등급 위** — 예측 가능해야 한다
5. **한 개체가 여러 레시피의 재료가 될 수 있다** — "이 리자드를 리자몽에 쓸까, 다른 조합에 쓸까"가 판단이 된다

### E-3. 레시피 규모 (초안)

| 결과 등급 | 레시피 수 | 재료 구성 |
|---|---|---|
| 안흔함 | 8 | 흔함 ×2 |
| 특별함 | 8 | 흔함 + 안흔함 |
| 희귀함 | 6 | 안흔함 + 특별함 |
| 전설 | 4 | 특별함 ×2 또는 특별함 + 희귀함 |
| **합계** | **26** | |

### E-4. 조각(Shard) 시스템 — 등급 합성의 대체

```
중복 포켓몬 방출  →  해당 등급 조각 획득
                     (흔함 1 · 안흔함 2 · 특별함 4 · 희귀함 8)
                            ↓
                  조각 상점에서 특정 재료 구매
                     (흔함 6조각 · 안흔함 14조각 · 특별함 30조각)
```

**목적**: "조합식에 딱 하나가 안 나와서 판이 끝난다"를 막는다. 확률을 통제하지는 못하되, 시간을 들이면 반드시 얻을 수 있는 경로를 준다.

## F. 등급 시스템

### F-1. 5등급 재정의

| 새 등급 | 내부 ID | 색 | 역할 | 해금 라운드 | 스킬 |
|---|---|---|---|---|---|
| 흔함 | `COMMON` | 회녹 | 초반 핵심 · 대부분의 재료 | 1 | 기본 공격만 |
| 안흔함 | `UNCOMMON` | 청 | 중반 주력 · 조합 재료 | 11 | 약한 특성 1 |
| 특별함 | `SPECIAL` | 보라 | 중상위 전력 | 21 | 특성 1 |
| 희귀함 | `RARE` | 호박 | 주요 전력 | 31 | **고유 스킬** |
| 전설 | `LEGENDARY` | 자홍 | 후반 핵심 | 41 | **고유 스킬 + 전설 패시브** |

> **주의: 내부 ID 를 그대로 재사용하면 안 된다.**
> 현재 `RARE` 는 2번째 등급인데 새 체계에서 `RARE` 는 4번째다. 문자열이 코드 103곳에
> 흩어져 있어 의미가 뒤바뀐 채로 동작하는 버그가 반드시 난다.
> **`TIER_1`~`TIER_5` 같은 중립 ID 로 한 번에 갈아엎고, 표시 이름만 한국어로 매핑한다.**

```js
RPD.Tiers = {
  T1: { id:'T1', label:'흔함',   color:'#8a9a8f', unlockRound:1,  skillLevel:0 },
  T2: { id:'T2', label:'안흔함', color:'#4f8fd6', unlockRound:11, skillLevel:1 },
  T3: { id:'T3', label:'특별함', color:'#a366e0', unlockRound:21, skillLevel:2 },
  T4: { id:'T4', label:'희귀함', color:'#f0a02e', unlockRound:31, skillLevel:3 },
  T5: { id:'T5', label:'전설',   color:'#ff5fa2', unlockRound:41, skillLevel:4 }
};
```

## G. 라운드별 소환 확률

### G-1. 확률표 (초안 — 밸런스 테스트로 조정)

| 라운드 | 흔함 | 안흔함 | 특별함 | 희귀함 | 전설 |
|---|---|---|---|---|---|
| 1–10 | 100% | — | — | — | — |
| 11–20 | 72% | 28% | — | — | — |
| 21–30 | 52% | 34% | 14% | — | — |
| 31–40 | 38% | 32% | 22% | 8% | — |
| 41–50 | 28% | 28% | 26% | 15% | 3% |

### G-2. 보정 장치

| 장치 | 내용 | 목적 |
|---|---|---|
| 해금 직후 보정 | 새 등급 해금 후 3라운드 동안 그 등급 확률 ×1.5 | 해금의 체감을 확실히 |
| 조합 보정 | 완성 직전인 레시피(재료 1개 부족)의 남은 재료 가중치 ×1.4 | "찾아가는 재미"를 좌절로 만들지 않는다 |
| 천장 | 희귀함 없이 40회 → 다음 소환 희귀함 확정 | 기존 천장 구조 재사용 |
| 중복 보정 | 이미 3마리 보유한 종의 가중치 ×0.5 | 같은 게 계속 나오는 좌절 완화 |

> **조합 보정은 이번 리디자인의 핵심 장치다.** 기획 38번의 「리자드가 나올 때까지
> 소환해보자 → 오! 나왔다」가 성립하려면, 완전 랜덤으로는 기대 소환 횟수가 너무 길다.
> 14종 중 1종을 노리면 평균 14회, 골드로는 600~1000G 다. 가중치 보정으로 평균 9회까지 낮춘다.

## H. 시너지

### H-1. 유지 + 위치 변경

현재 10종을 그대로 쓰되, **사이드바 패널 → 필드 오른쪽 고정 영역**으로 옮긴다.

| 타입 | 플레이 스타일 | 단계 |
|---|---|---|
| 불꽃 | 공격력 / 화상 | 2·4·6 |

## 마지막으로: 반드시 먼저 합의해야 할 4가지

### 1. 50라운드는 판 길이와 충돌한다 🔴

현재 20라운드가 **12분**이다. 라운드당 36초.
50라운드를 같은 템포로 돌리면 **30분**이 된다. 기획 22번의 "8~12분"과 정면 충돌한다.

**제안**: 경로 2510 → 1700px, 라운드당 목표 **13~15초**, 기본 2배속.
→ 50라운드 ≈ 12분. 대신 라운드 하나하나가 짧아져 적 수가 줄어든다.
**또는** 최종 라운드를 **40**으로 줄인다.

> 어느 쪽을 택할지 정해 주셔야 STEP 10(템포)의 목표치가 확정된다.

### 2. "대기시간 제거"와 "배치할 시간"은 실제로 충돌한다 🟠

전투 중 소환하면 새 포켓몬이 어디 앉을지 고민할 틈이 없다. 현재는 준비 시간에 드래그로 자리를 잡는다.

**제안**: 소환 시 **자동으로 최적 칸에 배치**하고(사거리에 맞는 빈 칸), 플레이어는 원하면 나중에 옮긴다. "배치를 강제하지 않되 개선의 여지는 남긴다."

### 3. 개체 수 55종 → 조합식 26개는 재료 확률을 매우 희석시킨다 🟠

흔함 16종에서 특정 1종을 노리면 평균 16회 소환이다. 골드로 **700~1000G**.
조합 보정(G-2)이 없으면 기획 38번의 체감이 안 나온다. **조합 보정은 필수다.**

### 4. 이번 작업은 사실상 "게임 2" 다 🔴

영향 범위를 실측하면:

| | 규모 |
|---|---|
| 전면 재작성 | `pokemon.js`(56종), `rarity.js`, `FusionManager`, `UIManager` |
| 대폭 수정 | `SummonManager`, `WaveManager`, `SaveManager`, `index.html`, `css` 3종 |
| 신규 | `recipes.js`, `RecipeManager`, `skills.js`, `SkillManager`, `ShardManager` |
| 폐기 테스트 | 약 160개 |
| 유지 | 전투 엔진, 보스, 필드, 모드, 스프라이트, 측정 도구 |

**PHASE 15까지 쌓은 밸런스 데이터는 대부분 무효가 된다.** 클리어율 41%·판시간 12.1분·
사망 분포 같은 수치를 처음부터 다시 잡아야 한다.

그래서 **기존 버전을 `v1-classic` 으로 보존하고 리디자인을 새 브랜치처럼 진행**할 것을 권한다.
리디자인이 기대만큼 안 나왔을 때 돌아갈 곳이 있어야 한다.
