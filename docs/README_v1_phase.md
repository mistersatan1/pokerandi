# 랜덤 포켓 디펜스

포켓몬을 랜덤으로 뽑고, 위치를 골라 배치하고, 합성으로 키워서 몰려오는 적을 막는 웹 디펜스 게임.
개인 팬 프로젝트이며 상업적 배포는 하지 않는다.

현재 상태: **PHASE 5 완료** — 웨이브가 돌고 적이 몰려오며, 못 막으면 게임 오버가 된다.
포켓몬 소환과 전투는 아직 없다 (PHASE 6~7).

## 실행

`index.html` 을 더블클릭한다. 로컬 서버가 필요 없다.

> ES 모듈 대신 클래식 script 태그를 쓰는 이유가 이것이다. 모듈을 쓰면 `file://` 에서 CORS 로 막혀
> 반드시 서버를 띄워야 한다.

서버로 띄우고 싶다면:

```bash
python3 -m http.server 8000   # http://localhost:8000
```

## 로스터 감축 (PHASE 15)

30판 측정에서 드러난 문제: **등급 합성이 96%를 차지하고 같은 종 합성은 판당 0.4회**였다.
소환 가능 종이 40개라 같은 종 3마리가 안 모이고, 같은 **등급** 3마리는 항상 모였기 때문이다.
기획 원칙("등급 합성은 구제 시스템")과 정반대였다.

### 무엇을 줄였나

| 항목 | 전 | 후 |
|---|---|---|
| 포켓몬 | 82종 | **56종** |
| 소환 풀 | 40종 | **25종** |
| 타입 시너지 | 17종 (6종 미발동) | **10종 (전부 발동)** |

삭제한 15계열: 캐터피·꼬렛·모래두지·주뱃·가디·식스테일·쥬쥬·니로우·잉어킹·메타몽·파이어·칠색조·루기아·세레비·**아르세우스**

기준은 셋이었다. ① 같은 등급·단계에서 모든 면이 열등한가 ② 역할이 다른 개체와 겹치는가
③ 피해를 독점하는가. 아르세우스는 혼자 전체 피해의 30%를 먹고 있었다.

### 등급 합성의 정체성 변경

골드 비용(35/80/180/400)을 물리고, **결과가 완전 랜덤이 아니라 보드에 이미 있는 종을
우선**하도록 바꿨다. 같은 종 합성과 경쟁하는 대신 그쪽으로 이어 주는 보조가 된다.

### 측정 결과

| 지표 | 감축 전 | 감축 후 |
|---|---|---|
| 같은 종 합성 | 0.4회/판 | **8.8회/판** |
| 각성 | 0.2회/판 | **1.5회/판** |
| 등급 합성 비중 | 96% | **71%** |
| 상위 3종 피해 점유 | 54% | **32%** |
| 단일 최대 점유 | 30.3% (아르세우스) | 18.0% |
| 미발동 시너지 | 6종 | **0종** |
| 방출 사용 | 0.3회/판 | **17.4회/판** |
| 판당 이자 | 131G | **404G** |
| 클리어율 / 판시간 | 36% / 10.2분 | 41% / 12.1분 |

난이도는 로스터가 강해진 만큼 웨이브 체력 배율을 1.178 → 1.202 로 올려 맞췄다.

**남은 과제**: 등급 합성 비중 71% 는 아직 높고, 슬롯 확장 구매가 판당 0.04 회로 죽어 있다.
둘 다 PHASE 17 밸런스 패스에서 100판 통계로 다시 잡는다.

## 게임 모드 4종 (PHASE 14)

게임 시작을 누르면 모드 선택이 뜬다. 모드별 최고 기록이 카드에 함께 보인다.

| 모드 | 목표 | 정체성 | 실제 차이 |
|---|---|---|---|
| 노멀 | 20웨이브 | 기준 | 시작 460G · 라이프 20 · 칸 16 |
| 엔드리스 | 무한 | 어디까지 가는지가 기록 | 보스 5웨이브마다 · 수입 +15% |
| 보스 러시 | 10웨이브 | 전부 보스 | 시작 690G · 수입 ×2.4 · 보스 체력 ×0.62 |
| 챌린지 | 20웨이브 | 여유가 없다 | 라이프 10 · **칸 12개** · 에픽 확률 7.1%(노멀 11%) |

**hpMul 만 다르면 "노멀인데 아픈 것"에 불과하다.** 그래서 모드마다 시작 골드·라이프·
칸 수·소환 확률·수입을 따로 조정하는 `modifiers` 를 뒀다. `selftest.js` 가
"어느 두 모드도 조건이 완전히 같지 않다"를 검사한다.

챌린지에서 막힌 칸은 골드로도 열 수 없고, 필드에 "사용 불가"로 표시된다.
(구현 중에 막힌 칸이 **비용 0이라 공짜로 구매 성공**으로 처리되던 버그를 테스트가 잡았다.)

**알려진 문제:** 보스 러시는 초반 편차가 크다(4판 실측 1·2·7·10웨이브).
잡몹이 없어 골드 공급이 보스 호위에만 의존하는 구조 탓이다.
표본 4판으로는 못 잡으므로 전용 밸런스 단계에서 30판 이상 놓고 다시 본다.

## 구조 수정 1차 (자체 평가 이후)

한 판을 끝까지 돌려 숫자를 재 봤더니 핵심 약속 네 개가 작동하지 않고 있었다. 전부 고쳤다.

| 문제 | 수정 전 | 수정 후 |
|---|---|---|
| 배치가 결과를 안 바꿈 | 16칸 중 12칸의 커버리지가 392px 로 동일 (편차 ×1.36) | 편차 **×5.06** · 같은 값 최대 2칸 |
| 등급 합성이 신화를 찍어냄 | 신화 = 커먼 81마리 → 매 판 신화 4종 전부 등장 | 신화 = 커먼 **315마리** · 등급별 필요 수 3/3/5/7 |
| 골드 판단이 없음 | 늘 빈털터리. 이자 실수령 0~1골드 | 이자 "10골드당 1" · **저축 250 전략이 탐욕형보다 유리** |
| 한 판이 너무 김 | 22.4분 (1배속) · 조작 346회 | **10.8분** · 조작 112회 · 노멀 20웨이브 |

**필드 좌표는 손으로 고르지 않고 탐색으로 찾았다.** 조건은 세 가지다.
① 칸이 경로와 겹치지 않는다 ② 커버리지 편차가 최대한 크다 ③ 짧은 사거리로 아무것도
못 때리는 칸이 최소 2개 있다. `selftest.js` 가 이 조건을 계속 감시한다.

**칸을 클릭하면 사거리별 커버리지가 막대로 보인다.** 배치한 포켓몬이 지금 몇 px 를
덮는지, 빈 칸 중 몇 곳이 더 나은지도 알려 준다. 숫자가 안 보이면 플레이어는 칸이
다르다는 걸 영영 모른다.

**실측 사망 분포 (30판 · 무전략 봇 기준)**

```
웨이브  3-5 : █████  5판   초반 운
웨이브 11-18: ██████████████ 14판  점진적 소모
웨이브 20   : ██  2판   최종 보스
클리어      : 9판 (30%)
```

특정 구간에 벽이 없고 고르게 퍼져 있다. 저축·배치·시너지를 챙기면 더 올라간다.

## 지금 되는 것

**가짜 버튼이 하나도 남지 않았다.** 하단 버튼 다섯 개가 전부 작동한다.

- 포켓몬 82종(소환 가능 40종) · 등급 5단계 · 역할 10종 · 타입 18종
- 랜덤 소환 + 천장 3종 + 웨이브 보정 + 보스 소환권
- 합성 4종 — 진화 / 분기 진화 / ★각성 / 등급 합성
- 타입 기본 효과 11종 + 타입 시너지 17종
- 보스 패턴 3종(증원·침묵·충격파) + 2페이즈 + 제한시간 돌진
- **강화** — 골드로 한 개체의 공격력을 +12%씩 최대 5회 (+60%)
- **슬롯 확장 2칸** — 220G / 480G. 잠긴 칸은 필드에 자물쇠와 가격이 그대로 보인다
- **저장** — 도감, 모드별 최고 기록, 누적 통계, 배속 설정

### 골드 쓸 곳이 네 갈래가 됐다

| 선택 | 성격 |
|---|---|
| 소환 | 운. 크게 먹거나 꽝이거나 |
| 강화 | 확실한 성장. 대신 한 마리만 |
| 슬롯 확장 | 공간. 두 레인을 한 사거리로 덮는 자리 |
| 아끼기 | 이자 4%(최대 40). 한 웨이브 굴린다 |

### 확장 칸은 왜 비싼가

기본 16칸은 한쪽 레인에 65px, 반대편에 145px이다. 사거리가 짧으면 한 레인만 때린다.
확장 칸 2개는 띠의 정중앙이라 **위아래 레인에서 똑같이 105px**이다.
사거리 하나로 두 레인을 다 덮는다. 값을 치를 이유가 위치 자체에 있다.

### 저장은 무엇을 남기지 않는가

한 판의 진행(웨이브·골드·보드)은 **저장하지 않는다.** 랜덤 디펜스는 매 판이 새로
시작하는 게임이고, 중간 저장은 "운이 나쁘면 되돌리기"를 만들어 판을 망친다.
판을 넘어 쌓이는 것만 남긴다 — 도감, 최고 기록, 설정.

사파리 프라이빗 모드처럼 `localStorage` 가 통째로 막히는 환경에서는
메모리에만 들고 가고, 사이드바에 그 사실을 표시한다. 저장 실패로 게임이 멈추지 않는다.

## 테스트

```bash
node tools/selftest.js         # 게임 로직 133개 (경로, 슬롯, 웨이브, 적, 경제, 기록)
node tools/bootsmoke.js        # index.html 순서대로 실제 부팅 → 버튼 클릭 → 한 판 진행
node tools/integritycheck.js   # HTML↔JS 연결, 로드 순서, 가짜 버튼 탐지
node tools/rendersmoke.js      # 렌더 코드 실행 (가짜 캔버스로 런타임 오류 탐지)
node tools/balance.js          # 난이도 곡선·골드 수급·포켓몬 설계 목표치 산출
```

다섯 개 모두 통과해야 다음 PHASE 로 넘어간다.

## 그래픽

**이미지 파일 없이도 82종 포켓몬과 12종 적이 각각 다르게 보인다.**
`js/render/SpriteFactory.js` 가 개체 데이터로 몬스터를 코드로 그린다.

```
tools/sprites.html 을 브라우저로 열면 94종 전부를 한눈에 볼 수 있다
```

규칙 세 가지
- 같은 개체는 언제나 같은 모습 (id 해시를 시드로 사용)
- 같은 계열은 닮았고 단계가 오를수록 커진다
- 타입이 실루엣에 드러난다 — 비행은 날개, 바위·강철은 각진 몸과 가시,
  물·얼음은 물방울 몸과 지느러미, 불꽃은 꼬리 불꽃, 전기·페어리·에스퍼는 귀

3단계와 보스는 눈매가 사나워지고, 각성체는 별도 스프라이트를 쓴다.
한 번 그린 결과는 캐시되므로 3배속에서도 부담이 없다.

### 진짜 그림을 넣고 싶다면

`assets/` 에 PNG 를 넣으면 **생성 스프라이트보다 우선** 적용된다. 코드 수정은 필요 없다.

```bash
node tools/assets.js          # 현황 표 (있음 / 없음)
node tools/assets.js --write  # assets/MANIFEST.md 갱신
```

`assets/MANIFEST.md` 에 필요한 파일 94개의 정확한 이름과 규격이 있다.
PNG 투명 배경 · 포켓몬 96×96 · 적 64×64 · 보스 128×128 권장.
렌더러가 `imageSmoothingEnabled = false` 로 그려서 픽셀 아트가 뭉개지지 않는다.

점검 도구는 누락 파일, 두 개체가 같은 파일을 참조해 덮이는 경우,
폴더에 있지만 아무도 안 쓰는 파일(이름 오타)을 함께 잡아 준다.

## 폴더 구조

```
js/core/      엔진 (게임 규칙을 모름)
js/data/      순수 데이터 (로직 없음)
js/systems/   게임 규칙 (DOM 을 모름)
js/render/    캔버스 그리기 (규칙을 모름)
js/ui/        DOM (여기만 document 를 안다)
tools/        테스트 스크립트
docs/         기획서
```

포켓몬 하나를 추가하려면 `js/data/pokemon.js` 의 `LINES` 배열에 진화 라인 하나를 적으면 된다.
단계별 스탯은 자동으로 펼쳐진다. 다른 파일은 건드리지 않는다.

전체 기획과 밸런스 수치는 `docs/GAME_DESIGN.md` 참고.
