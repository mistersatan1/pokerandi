# Game UI Frontend — 포랜디

## 목표
웹페이지가 아니라 게임처럼 느껴지는 HUD와 인터랙션을 만든다.

## 기본 구조
가능하면 상단에는 라운드/보스/재화, 중앙에는 전투 필드, 측면에는 시너지/조합, 하단에는 핵심 행동 버튼을 배치한다. 실제 코드 구조를 먼저 확인하고 적용한다.

## HUD
항상 보여야 하는 정보:
- 현재 라운드
- 현재 재화
- 전투 상태
- 핵심 행동 버튼

상황에 따라 보여줄 정보:
- 조합 가능 정보
- 유닛 상세
- 시너지 상세
- 보상
- 도감

## 유닛
기본 표시: 스프라이트, 이름/식별 정보, 등급, 핵심 수치.
상세 정보는 선택/호버에서 보여줄 수 있다.

## T1~T5
등급 차이를 색상 하나로 끝내지 않는다.
- T1: 단순하고 빠른 피드백
- T2: 약간의 강조
- T3: 확실한 존재감
- T4: 특별한 존재감과 스킬 강조
- T5: 등장 자체가 이벤트처럼 느껴지는 수준
단, 전투를 방해할 정도의 연출은 금지한다.

## 조합식
재료 → 결과 관계가 즉시 보이게 한다.
- 보유 재료 강조
- 부족한 재료 표시
- 조합 가능 상태 강조
- 조합 성공 시 짧은 애니메이션

조합 패널 때문에 전투 필드가 좁아지지 않게 한다.

## 시너지
TFT의 정보 전달 방식은 참고할 수 있으나 그대로 복제하지 않는다.
아이콘, 현재 활성 수치, 활성 단계, 다음 단계 조건을 명확히 표시한다.
활성화 순간에는 짧은 피드백을 준다.

## 버튼
Primary: 소환/핵심 행동
Secondary: 강화/상점/도감
Tertiary: 설정/부가 기능
모든 버튼을 동일하게 강조하지 않는다.

## 오버레이
보스, T4/T5, 조합 성공 같은 특별 이벤트에만 강한 연출을 사용한다. 짧고 명확하며 게임플레이를 방해하지 않아야 한다.

## 성능
DOM 과다 생성, layout thrashing, 불필요한 interval/requestAnimationFrame, 중복 이벤트 리스너를 피한다. UI 변경 전에 기존 상태 관리와 이벤트 연결을 조사한다.
