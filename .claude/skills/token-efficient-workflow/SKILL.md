# 토큰 효율 작업 방식

품질을 낮추지 않고 불필요한 컨텍스트만 줄인다. 아래 절약 규칙보다 요구사항, 보안, 데이터 무결성, 테스트 결과가 항상 우선한다.

## 탐색
- 작업과 직접 관련된 파일만 읽는다. Grep/Glob으로 위치를 먼저 좁힌다.
- 이미 확인한 구조·명령어는 이유 없이 다시 조사하지 않는다.
- 큰 파일은 offset/limit으로 필요한 구간만 읽는다.
- 전체 소스나 전체 로그를 출력하지 않는다. 실패 로그는 오류 줄과 앞뒤 몇 줄만 본다.

## 구현
- 수정 전에 대상 파일과 이유를 한두 줄로 제시한다.
- 작은 변경을 작은 단위로 구현하고 바로 검증한다.
- 오류가 나면 반복 실행하지 말고 실패 원인부터 좁힌다. 같은 명령·탐색을 반복하지 않는다.

## 테스트
- 변경 범위에 맞는 테스트를 선택해 실행한다.
- 핵심 계산, 저장 데이터, 권한·보안 관련 테스트는 변경과 관련 있으면 생략하지 않는다.

## 스킬·에이전트
- 평소에는 이름만 보이는 스킬이 많다. 디자인·애니메이션·기획 같은 특정 작업을 시작할 때만 `skill-catalog`를 읽고 필요한 스킬 1~2개를 불러 쓴다.
- 서브에이전트는 독립된 큰 작업에만 쓴다. 작은 작업은 직접 한다.

## 보고
- 변경 사항, 테스트 결과, 남은 위험 순서로 짧게 요약한다.
- 실행하지 않은 검증은 "미검증"으로 적는다.
- 새 세션에서 이어갈 필요가 있을 때만 핵심 진행 상태를 짧게 문서화한다.
