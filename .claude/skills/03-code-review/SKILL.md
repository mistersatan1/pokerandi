# Code Review

## 검토 순서
1. 변경된 파일과 diff를 확인한다.
2. 기존 동작을 깨뜨릴 가능성을 찾는다.
3. 상태 관리와 데이터 흐름을 확인한다.
4. 예외 상황과 빈 데이터 처리를 확인한다.
5. 중복 코드와 지나친 복잡성을 확인한다.
6. 성능 문제가 될 수 있는 반복 연산을 확인한다.
7. 저장 데이터 호환성을 확인한다.
8. 테스트가 부족한 부분을 제시한다.

## 출력
심각도별로 정리한다:
- CRITICAL: 즉시 수정해야 하는 치명적 문제
- HIGH: 실제 플레이/사용 중 오류 가능성이 높은 문제
- MEDIUM: 특정 조건에서 문제가 될 수 있는 문제
- LOW: 유지보수성 또는 개선 사항

문제가 없다면 "검토상 발견된 문제 없음"이라고 명확히 말하고 검토 범위를 적는다.
